# Система распределения заказов такси

Простой Telegram-бот заказа такси для небольшого населённого пункта.

- Без тарификации и карт — только выбор точек маршрута из списка.
- Возможность ввести свой адрес текстом.
- Корректное распределение заказов между водителями: первый принявший получает заказ (атомарно), очередь справедлива по времени последнего заказа.

## Возможности

**Клиенту:**
- Создать заказ: откуда → куда → комментарий → подтверждение.
- Видеть статус и контакты назначенного водителя.
- Отменить активный заказ.

**Водителю:**
- Регистрация по коду от администратора.
- Онлайн/оффлайн переключение.
- Получение новых заказов с кнопкой «Принять».
- Управление активным заказом: «Начать поездку», «Завершить», «Отказаться».
- Просмотр очереди свободных заказов.

**Администратору:**
- `/stats` — статистика заказов и водителей.
- `/drivers` — список водителей с возможностью удаления.
- `/orders` — свободные заказы в очереди.

## Установка

```bash
git clone https://github.com/rustobbay-cmd/taxi-dispatch-bot.git
cd taxi-dispatch-bot
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Отредактируйте `.env`:

```
BOT_TOKEN=токен_от_@BotFather
ADMIN_IDS=123456789            # ваш Telegram ID, через запятую
DRIVER_REG_CODE=change_me_to_a_private_code       # код, который выдаёте водителям для регистрации
DB_PATH=taxi.db
```

Узнать свой Telegram ID — напишите `/start` боту `@userinfobot`.

## Запуск

```bash
python bot.py
```

База `taxi.db` создастся автоматически при первом запуске.

## Настройка списка точек

Отредактируйте `locations.py` под свой населённый пункт — добавьте улицы, магазины, районы.

```python
LOCATIONS = [
    ("center", "Центр"),
    ("station", "Ж/Д вокзал"),
    # ...
]
```

## Как подключить водителей

1. Зарегистрируйте бота у [@BotFather](https://t.me/BotFather), получите токен.
2. Запустите бота.
3. Дайте водителям код из `DRIVER_REG_CODE`.
4. Водитель открывает бота, пишет `/driver`, вводит код, заполняет ФИО/телефон/авто.
5. Нажимает «🟢 Выйти на линию» — готов принимать заказы.

## Логика распределения заказов

1. Клиент подтверждает заказ → статус `new`.
2. Сервис вызывает `broadcast_order_to_drivers`:
   - Берёт всех онлайн-водителей **без активного заказа**.
   - Сортирует по `last_order_at` ASC (сначала самые «голодные»).
   - Каждому отправляет сообщение с кнопкой «✅ Принять».
3. Первый нажавший «Принять» выполняет атомарный `UPDATE orders SET driver_id=?, status='assigned' WHERE id=? AND status='new'`. Если `rowcount != 1` — заказ уже забрали, пользователь видит alert.
4. Клиенту уходит уведомление с контактами водителя.
5. Если водитель отказался — статус заказа возвращается в `new`, рассылка запускается заново.
6. Если никого нет на линии — клиент уведомляется. Как только кто-то выходит на линию — ему сразу предлагаются висящие заказы.

## Структура проекта

```
taxi-dispatch-bot/
├── bot.py                 # точка входа
├── config.py              # загрузка .env
├── database.py            # SQLite через aiosqlite
├── keyboards.py           # клавиатуры
├── states.py              # FSM
├── locations.py           # список точек города
└── handlers/
    ├── common.py          # /start, /help, /cancel
    ├── client.py          # поток заказа + broadcast
    ├── driver.py          # регистрация, приём, поездка
    └── admin.py           # /admin, /stats, /drivers, /orders
```
